**Все официальные источники по Щецину этой ночью оказались недоступны** — не прокси-блок (EGRESS_BLOCKED), а похоже на блокировку/нестабильность самих сайтов для исходящего IP этой сессии. Проверял и через `WebFetch`, и через `curl` (с `--cacert /root/.ccr/ca-bundle.crt`), по нескольку попыток на каждый адрес:

|---|---|
| `https://www.gov.pl/web/uw-zachodniopomorski/oplaty-skarbowe` | `curl`: connection reset (3/3 попыток). `WebFetch`: HTTP 503 |
| `https://www.gov.pl/web/udsc/oplaty` | то же самое |

| `https://bip.um.szczecin.pl/chapter_11037.asp` | `curl`: HTTP/2 protocol error → `--http1.1`: empty reply. `WebFetch`: HTTP 502 |

Контрольная проверка: `https://www.katowice.uw.gov.pl/` открылся нормально (HTTP 200) тем же способом — то есть проблема не в проксе в целом и не в домене `*.uw.gov.pl` вообще, а конкретно в источниках по Щецину (gov.pl-домен и его конкретные поддомены/старые ASP-сайты города). `www.szczecin.eu` открывается (через `curl -L`, финальный код 200), но на нём нет ни страницы «opłata skarbowa», ни номера счёта — поиск по странице это подтвердил.

Из-за этого блокера **я не вставил ни одного номера счёта, ни адреса, ни телефона/email, ни часов приёма** — по правилам задачи это разрешено вставлять только при личном открытии официальной страницы через WebFetch/curl, а сниппет поисковика не считается источником. WebSearch несколько раз выдавал "вероятный" номер счёта города (встречался на вторичных и части официальных страниц в сниппетах — `20 1020 4795 0000 9302 0277 9429` для Urzędu Miasta Szczecin), но раз я не смог открыть исходную страницу сам — в файл этот номер **не попал**, только явные плейсхолдеры.
